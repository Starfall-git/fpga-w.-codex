## 接口与数据格式

模组仍连接原来的20针DVP排座。由两块模组与底板原理图逐针核对：

| 排针 | FPGA信号 | AR0135模组信号/作用 |
|---|---|---|
| 3 / 4 | cmos_sclk / cmos_sdat | I2C，7位地址0x10，线上写0x20/读0x21，SADDR=0 |
| 5 / 6 | cmos_vsync / cmos_href | FRAME_VALID / LINE_VALID，高有效 |
| 7 / 8 | cmos_pclk / cmos_xclk | 74.25MHz输入像素时钟 / 27MHz输出参考时钟 |
| 9–16 | cmos_data[7:0] | 接传感器DOUT[11:4]，舍去低4位 |
| 17 | 没有对应FPGA顶层端口 | RESET_BAR由摄像头模组上拉/RC控制；RTL再执行软件复位 |
| 18 | cmos_ctl1 | FLASH输出，FPGA必须OE=0，避免双方驱动 |
| 19 | cmos_ctl2 | TRIGGER，保持0，自由运行 |
| 20 | cmos_ctl3 | OE_BAR，保持0，允许传感器输出 |

没有把数据总线改成12根线，因为排座只引出高8位。保留底板原来的电平转换和I/O标准配置；不能简单把所有摄像头引脚统一改为1.8V或3.3V。

灰度转换为 `{raw[7:3], raw[7:2], raw[7:3]}`（RGB565），每个PCLK写一个16位像素。DDR帧长度仍是1280×720×2字节。`axi_transform_reader`、后级Sobel与UART控制器无需改变。

## 初始化与帧采集

1. 系统/DDR/摄像头PLL锁定后等待20ms，再读取0x3000型号寄存器。
2. 写0x301A=0x10D9软件复位，真正等待10ms；等待表项不会向地址0x0000写入数据。
3. 27MHz ×44 ÷2 ÷1 ÷8 =74.25MHz；PLL配置后等待2ms，开流前再等待2ms。
4. 源窗口X=0..1279、Y=120..839，共1280×720；行长1650、帧长747，名义采集约60.24fps。HDMI时序仍沿用原74.4MHz配置，两侧由DDR解耦。
5. 寄存器0x3040=0，取消示例的传感器内部垂直翻转；由上位机几何模块统一控制翻转。
6. 0x3028=0x0010：数据/FV/LV在PCLK下降沿附近变化，FPGA外设输入寄存器保持上升沿采样，依据寄存器手册第14页和datasheet第14页。资料包Ti60示例设置了相反采样沿，本版本没有照抄该项。
7. 保留自动曝光/自动增益0x3100=0x0013，并显式设置0x3064=0x1982。手册第21页明确AE依赖元数据和统计行，不能直接关闭。采集跳过前2行，取其后720行，丢弃尾部2行统计数据。初始曝光和AE最大曝光设672行，避免示例960行曝光长于当前帧。
8. 配置完成经过像素域同步；先看到FV低，再从下一帧开始采集，避免把上电残帧当成完整图像。

I2C使用100kHz，SDA只驱动0或释放，上拉产生高电平；每个发送字节都检查ACK。失败后等待1ms，最多重试3次，仍失败则停止并保持`done=0,error=1`，系统复位后重试。型号读回值保留在模块输出`camera_model_id`，不按单一ID硬锁死，以免芯片修订差异阻断初始化。未新增上位机型号查询命令。

## 上板观察

**使用本目录的 `Ti60_AR0135.xml` 作为本版本工程入口。** 当前打开的旧 `Ti60_Demo.xml` 会反复回写旧文件列表，因此新增独立入口；两者使用同一份顶层和RTL。新入口同时配有同名 `.peri.xml` 和 `.pt.sdc`，必须一起保留；Efinity命令行会按工程名称寻找外围文件。请在Efinity打开新入口后再编译，不要从旧窗口编译。原始官方demo不受影响。

下载本版本bit后应先看到原始灰度图，再依次测试Sobel、阈值、反相、翻转、裁剪、缩放及默认恢复。LED[3:0]仍对应DDR校准通过、DDR校准完成、摄像头PLL锁定、系统PLL锁定；LED4表示初始化完成，LED5是FV帧计数心跳（点亮极性按板卡电路）。

- LED4不进入完成状态：检查SADDR=0和I2C应答、模组供电、27MHz XCLK及RESET_BAR是否释放。
- LED4完成但LED5不变化：检查传感器PCLK/FV、排线方向与OE_BAR。
- 有帧但错行：检查LV每帧行数是否为2+720+2，并确认寄存器0x3064；采集过滤规则与该寄存器必须一起修改。
- 若原图采样不稳，应测量PCLK相对数据的实际时序，再调整I/O采样延迟；不能只看综合通过。
