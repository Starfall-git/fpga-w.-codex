## 功能范围

从原始1280×720摄像头图像中自动选择一个手部候选，生成可变位置、可变大小的正方形裁剪，再执行原有五类手势分类。没有固定中央位置限制。多只手时仅处理最高分候选，尚不是多手同时识别器。检测所有有标注的手（包括no_gesture），分类阶段再拒绝不属于五种手势的姿态。

任意位置不代表任意大小、遮挡或速度都保证检出。低分结果会被拒绝；边缘处裁剪平移到画面内。摄像头近距离大手、很小远处手、快速移动和严重遮挡需要另行实拍评估。

## 结构与硬件安排

采用中心点/尺寸预测思路，参考 [Objects as Points](https://arxiv.org/abs/1904.07850)，但这是自主实现的小网络，并非论文原始CenterNet结构或其预训练权重。

1. 对全画面作5×5区域平均，得到256×144灰度检测输入。
2. 三层3×3步长2卷积，通道4、8、16；一层3×3步长1、膨胀率2、通道32卷积；最后1×1卷积输出32×18×5。
3. 每个网格输出手部logit、网格内中心dx/dy、归一化宽/高。选择一个候选，转换为64倍数、64..704像素的裁剪窗口。
4. 在随后摄像头帧内对该窗口区域平均到64×64，再运行v1.1分类器。
5. 再次全画面定位，循环执行。没有仅在旧位置附近搜索的永久锁定，因此手离开旧位置后可重新定位。

定位和分类复用一个INT8乘加器、18432和36864字节两组特征RAM、20908字节拼接权重ROM；相机邮箱36864字节。第四层检测卷积使用膨胀率2扩大空间上下文，MAC数量不随膨胀率增加。检测头五个输出使用独立量化尺度，避免物体分数的大权重压低框坐标的量化分辨率。

摄像头端256列累加器和流水线定点倒数乘法完成区域平均。对block=1..11的所有可能像素和已穷举核对，与精确四舍五入整数除法一致。两种模式保持整帧邮箱所有权；请求、应答、启动控制跨域同步，坐标总线在应答前保持稳定，再在新帧边界锁存。推理繁忙时跳帧，不阻塞原视频。

检测使用较早的一帧，分类使用随后的一帧。快速运动可能使裁剪与实际手位置偏离，不能把这个流程当成同帧检测分类或连续光流跟踪。

## 数据与训练

使用 [HaGRID原始手框标注](https://github.com/hukenovs/hagrid) 和v1.1同一公开图片子集，继承原作者人员划分及跨组原图SHA256排除清单。重取完整图片，记录字节哈希并核对一致性，缩放保持宽高比、灰度补边到1280×720，保存JPEG。模型输入再缩到256×144。图像许可继续遵循 [v1.1数据来源记录](../ml/gesture/DATA_SOURCES.md)。

训练标注来自手框，不使用肤色阈值冒充神经网络检测器。只使用原标注无手重叠的背景裁剪作为负样本。增强同时变换图像和手框，包括平移、缩放、翻转、亮度/对比度。定位检测指标与分类准确率分开报告；测试集不参与模型检查点或门限选择。量化导出设置最低离线门槛：验证集IoU≥0.5的候选精确率至少85%、有手场景召回至少50%；未达标仅保留诊断报告，不写入部署ROM，也不读取测试集。该门槛不是实际摄像头可靠性保证。

`ml/detector/prepare.py` 支持缓存续传；`data/failures*.json` 保留失败记录。文件处理失败不能当作成功样本。`train.py` 强制检查人员、来源ID、原图哈希不跨分组。下载未完成时不发布完整训练结果。

## GUI和协议

v1.2状态版本为0x12，v1.1仍为0x11。主机可识别两种固件。

- 0x40/0x41状态与启停布局不变，版本字段区分自动/固定位置模式。
- 新增0x42读取最近检测裁剪：8字节为status、0x12、xLE16、yLE16、sideLE16。
- side=0时没有有效定位，x/y同时清零。坐标表示最新检测窗口，并非带视频的可视化边框或识别概率。
- GUI显示全画面模式说明和实际回传位置；旧固件继续提示中央区域，不会冒充自动定位。
- 摄像头图像仍走HDMI，GUI没有接入HDMI采集。暂停、回放及显示侧ISP不改变识别源。
