# V0.15 DDR帧仓库、HDMI回放对比与本地编辑

2026-09-29 完成验证与导出。源码版本注释沿用2026-09-28开始实施的V0.15。
本说明替代V0.14中的串口图像下载流程；历史说明仅供版本追溯。

## 上板与操作

使用 `Ti60_AR0135.xml` 工程。下载 `outflow/Ti60_AR0135_v015_ddr_store_replay_compare.bit`，然后在工程根目录运行：

```powershell
D:/python/python.exe -m pip install -r host/requirements.txt
D:/python/python.exe -m host.gui
```

1. 连接115200串口后查看DDR仓库状态。串口仅发送控制、帧编号和状态，**不再回传像素**。
2. **帧冻结**：将当前直播显示帧对应的DDR槽保留下来，屏幕继续直播。重复操作最多保存8帧。
3. **暂停**：保持当前显示帧；摄像头和DDR后台采集继续运行。暂停不会自动向仓库新增记录。
4. **继续**：退出暂停、单帧回放或多帧对比，恢复直播。已保存帧不删除。
5. **DDR冻结帧仓库**：显示板上帧编号和当前数量/上限。选择一帧，点击 **回放选中帧**，HDMI显示该帧。按Ctrl/Shift多选后点击 **HDMI对比所选**。
6. 选中1～8帧时采用1×1、2×1、2×2、3×2或3×3排列，按编号升序、从左到右、从上到下显示。等比例缩放，空单元和边缘补黑。满8帧时不能新增，点击 **清空DDR仓库**可释放全部记录。
7. **默认**恢复原有图像处理默认值并返回直播，保留Sobel阈值及已保存DDR帧。

只有直播状态可以新增冻结记录；暂停/回放/对比时先点继续。多帧对比固定显示各帧的完整源画面，此时GUI禁用几何裁剪/缩放/翻转控制；回到直播后保留的单帧几何配置再次生效。

DDR中保存的是摄像头RGB565源帧，不是处理后的HDMI截图。回放会经过当前图像处理设置，因此可以对同一保存帧切换Sobel、中值或阈值。多帧对比先进行几何拼图，再经过现有ISP；它不是分别保存多张已处理成图。

## DDR容量和帧保护

本版配置12个槽，每槽保留原有4MiB地址步长，共预留48MiB地址空间，最多固定保存8帧，其余4个槽用于直播读写调度。1280×720 RGB565实际有效图像为1,843,200字节。**8帧是本版软件/RTL配置上限，不是整块DDR物理容量的理论上限。** 扩容需要同步修改槽数、索引位宽、协议掩码、布局与带宽验证，不能只改GUI数字。

帧编号对应0～11的槽编号，已保存的编号不会被写入器覆盖；清空后编号可被再次使用。DDR是易失存储，复位、重新下载bit或断电后这些记录失效。电脑仓库中的PNG文件不受影响。

`ddr_frame_store`在读通道排空、读帧安全边界处理命令。写入器每次换帧排除当前读槽和所有保存槽；保存操作固定当前读槽但保持直播模式。回放只能选择已保存槽；仓库满返回错误，不覆盖旧帧。

## 两种仓库与HDMI接口

- **DDR冻结帧仓库**：当前仅列编号，无缩略图；控制板卡HDMI输出。图片不能通过串口下载到电脑。
- **本地图片仓库**：保留既有PNG、缩略图、批注、裁剪、缩放、镜像、另存、导出和多图比较。默认目录为 `~/Pictures/VF-Ti60-FrozenFrames`。编辑生成新副本，不覆盖原图。
- **HDMI预览**：现阶段显示采集通路未接入，保存按钮禁用。没有伪造预览或回退到串口传图。

预留接口位于 `host/hdmi_source.py`：

```python
class HDMIFrameSource(Protocol):
    @property
    def available(self) -> bool: ...
    def latest(self) -> HDMIFrame | None: ...
    def close(self) -> None: ...
```

`HDMIFrame`携带PIL图像、递增sequence和timestamp。以后由HDMI采集设备适配器在自己的后台线程取帧，`latest()`必须非阻塞，并返回在GUI使用期间保持稳定的图像。通过 `ImageControlApp(root, hdmi_source=adapter)` 注入。预览窗口约33ms检查最新帧，已经接好显示和保存到本地仓库的调用端；硬件采集适配器本次未实现。DDR帧编号与未来HDMI采集帧的精确对应还需在通路接通后验证延迟和同步，不能把任意最新采集帧冒充指定DDR编号的缩略图。

## 编辑器移动、居中与铺满

- 选择 **拖动图像** 后左键拖动，或使用鼠标中键拖动。
- 工具栏上下左右按钮移动图像；点击画布获得焦点后，键盘方向键微调。
- **自适应居中**：完整显示图像并将中心放到显示框中心。
- **铺满显示框**：保持宽高比放大到覆盖整个显示框，超出框的部分可拖动查看，不拉伸图像。
- 裁剪完成后自动适应居中，可继续铺满；放大或缩小后同样支持平移。
- 平移和查看缩放只影响视图，不改文件像素。画笔和裁剪坐标会扣除视图平移并除以缩放倍率；导出和另存使用实际编辑后的图像，不截取屏幕视口。

## 串口V2控制协议

沿用13字节帧 `A5 5A SEQ CMD DATA[8] CRC8`，CRC8覆盖SEQ、CMD、DATA，poly07/init00，命令号以下均为十六进制。

- **30**：请求DATA全零，查询仓库状态。
- **31**：DATA byte0操作，byte1帧号，byte2..3小端选择掩码，byte4..7零。
- 操作0继续、1保存当前直播帧、2暂停、3按byte1回放、4按掩码对比、5清空。未使用字段必须零。
- **32**：已删除图像读行功能，返回未实现状态3；无后续像素流。

30/31成功或已执行31的应答DATA为：`[result, 2, capacity, count, maskLo, maskHi, mode, displaySlot]`。mode=0直播、1暂停、2回放、3对比；对比时displaySlot不是全部对比槽列表，应使用请求掩码。已保存mask占低12位。

result=0成功、2参数/编号无效、4当前状态不允许保存、5等帧边界超时、7仓库满。参数/超时等错误可用既有标准错误应答；软件先判断result，不能把错误包按成功状态解析。31应答在DDR帧边界完成后发出。30/31的版本2用于拒绝旧版串口传图协议；其它既有图像控制命令保持兼容。
