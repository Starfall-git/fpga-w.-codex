## 与参考算子的关系

窗口为 `a b c / d e f / g h i`，计算：

```text
G0   = abs(g + 2h + i - a - 2b - c)
G45  = abs(f + 2i + h - b - 2a - d)
G90  = abs(c + 2f + i - a - 2d - g)
G135 = abs(b + 2c + f - d - 2g - h)
M = max(G0,G45,G90,G135)
```

反方向的绝对值相同，所以四组运算覆盖八方向。各分量及M范围0～1020，使用显式有符号11位运算避免溢出。
参考代码直接判断 `M >= e`。本版默认判断：

```text
T = max(串口阈值, e, 1)
M >= T：白色；否则黑色（GUI黑白反转可交换）
```

最低门限1修复参考代码在全黑输入时0>=0导致的白色输出；串口下限继续让用户控制抑噪强度。
设置SOBEL_ADAPTIVE=0后，T只等于串口阈值，包括阈值0时所有有效像素通过的原有语义。
开启自适应时，阈值降到中心亮度以下可能不再改变对应区域，这属于硬件门限行为，不是GUI延迟。
阈值协议仍为0～4095；大于1020会滤掉全部有效边缘。无效边界正常模式黑、反相模式白，消隐始终黑。
GRAYSCALE_OUTPUT诊断模式保留旧工程的 `min(M,255)`，没有复制参考的 `min(M/2,255)`。

八方向最大值不是非极大值抑制，也不会自动把多像素边缘细化为一像素或连接断线。
中心亮度门限可能抑制亮区域中的低对比度文字；中值滤波可以去除孤立噪声，也可能抹掉很细的笔画。
两张照片的摄像头、场景、对焦、照明及阈值不一致，不能据此保证移植后画质等同。

## AR0135是否需要转灰度

黑白传感器本来就输出亮度，Sobel需要单通道亮度，不需要再做彩色加权。
若R=G=B=Y，旧公式(R+2G+B)/4和新公式(306R+601G+117B)/1024都严格得到Y，旧近似本身不会破坏边缘。
但当前采集把RAW8打包为 `{raw[7:3],raw[7:2],raw[7:3]}` 存入RGB565，读出补零：
R/B为raw向下取8的倍数，G为raw向下取4的倍数。因此旧公式相对G会低0或2灰度级；
相对原RAW8最大损失5级，新旁路G最大损失3级。阈值附近少数点会受影响，不能把严重噪点/模糊全部归因于灰度公式。
新模块选择保留位数更多的G；没有改变DDR格式，也不能恢复已经舍弃的低两位。
彩色RGB输入则应ENABLE_GRAY=1，公式为参考工程的306/601/117权重，系数和恰好1024。

## 时序与既有功能

灰度3拍 + 中值窗口2拍 + 中值3拍 + Sobel窗口2拍 + Sobel3拍 = 13拍。
未启用中值时，灰度延迟5拍后进入Sobel窗口；中值输出额外延迟5拍用于单独显示。
原图延迟13拍，四种模式统一使用末级HS/VS/DE。模式仍由UART在场消隐更新，GUI协议不变。
这些是时钟流水延迟；因3×3因果窗口带来的空间偏移仍保留，未新增中心像素几何补偿。
保留V0.10的像素有效位、左上8像素边界保护和摄像头方向修复。

## 上板比较方法

1. 使用同一场景、相同光线，先保持100%倍率和全图，关闭Sobel，调焦确认文字本身清晰且未过曝。
2. 同时开启中值和Sobel，以默认128为起点。尝试64、96、128、160，观察笔画完整性与背景噪声；这是调试起点，不是已实测的最优参数。
3. 关闭中值对照：若细字恢复但噪点增加，说明中值对细节有影响；若原图已经模糊，应优先解决镜头/曝光/运动模糊。
4. 自适应模式下亮区文字缺失且降低串口阈值无效时，编译SOBEL_ADAPTIVE=0作固定门限对照。
5. 对比时保持1倍缩放；最近邻缩放会重复/丢弃像素，改变笔画与Sobel结果。
