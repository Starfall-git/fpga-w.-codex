# V0.19 曝光增益与可选图像算法优化

本版基于已完成的V0.18，保留DDR仓库、回放/多帧对比、USB采集、本地批注和几何变换。新增功能均可回到原设置；没有改写`video_processing`的分模块框架，也没有改动`sobeledge_8d_window.v`的Sobel算术。

## 交付与使用

- 工程：`Ti60_AR0135.xml`。
- 比特流：`outflow/Ti60_AR0135_v019_exposure_isp_tuning.bit`，2,355,225字节。
- SHA256：`5a0fa733212396f4f10c13ce8f6c75d4eba6a8eb40f19f85d4e093658a7faa42`。
- 上位机：在工程根目录运行 `D:/python/python.exe -m host.gui`，或`host/start_gui.bat`。
- 备份：`tools/debug/before-v019/`保存本轮编辑前的主要文件；旧V0.18 bit仍保留。

连接新版硬件后，点击主界面“曝光 / 算法调节”。没有向板卡下载或清空DDR，本次交付需要你上板验收。新GUI可以控制旧bit已有功能，但旧bit不会开放曝光调节入口。旧GUI不认识新的扩展能力31，应一起更新。

1. 先关闭边缘检测观察原图，检查是否太暗、过曝或运动模糊。
2. 点击“自动调光”，立即开始重新配置传感器AE；稳定需要若干帧，面板会在空闲时每秒回读。AE优化的是亮度，并非直接搜索最清晰的边缘。
3. 需要手动时，拖动曝光/模拟增益/数字增益，松开后提交；串口忙时只保留最新一组手动值。曝光优先，模拟增益其次，数字增益尽量保持1×。自动模式下读回AE实际曝光和增益；手动模式读回设置寄存器。
4. Sobel沿用原阈值和中值开关；细密噪点明显时开启高斯，再勾选“增强高斯”比较。它会平滑小文字和细纹理，不能把所有纹理都判断为噪声。
5. Scharr可打开“幅度方向修正”，斜边亮度和阈值响应会变化，需要重新比较阈值。
6. Canny可用“尝试降噪与连续轮廓组合”：双级高斯、幅度修正、六轮连接，低阈值为高阈值的50%。主界面Canny开关会启用高斯；组合按钮本身不替你切换边缘算法。低阈值降低可留住弱边，也可能连接噪点；提高则相反。Sobel阈值0时的灰度强度画面不能直接等同于Canny高阈值0；后者会接受大量微小梯度。
7. “孤立候选抑制”只删除没有任何邻接候选的点，默认关闭，可能丢失很小的细节。它不是大连通域面积筛选。
8. 主界面“默认”在FPGA内恢复算法和摄像头上电配置，保留Sobel阈值和DDR中已记录的帧；自动调光修改的测光区域/增益切换门限也会回到原上电值。

## 弱光噪声及自动调光的分析

低照度时信号弱；增益会同时放大有效信号和部分噪声，曝光过长又会造成运动模糊。中值对孤立脉冲有效，但对细密随机波动、真实纹理和低频光影波纹未必有效。不能只提高边缘阈值，否则弱轮廓会一起断裂。

本工程原先`0x311C=672`限制最大AE曝光为672行。手册给出`0x3166`默认986行，作为自动模拟增益提升的曝光门限；这高于当前上限，是自动调光不灵敏的一个可疑配置因素，尚非实测根因。原测光ROI高度默认960，而当前有效画面720行。

“自动调光”依次停AE、固定数字增益1×、设置目标亮度1280与阻尼上限320、将ROI设置为(0,0,1280,720)、模拟增益提升/降低门限改为600/400行、最后启用AE和自动模拟增益（`0x3100=3`）。它不复位传感器、不重建DDR，也不保证立即达到最优画质。上电/默认保留旧AE行为（`0x3100=19`、ROI高度960、切换门限986/419），方便对照。

曝光1～672行，按当前27MHz输入及传感器PLL、1650像素行周期，单行约22.222µs，因此672行≈14.933ms。界面毫秒是配置推算值。模拟增益1/2/4/8×；数字增益32～128对应1～4×。自动增益的实际值不会用手动设置值冒充，读取`0x312A`和`0x3164`。调整期间可能跨越传感器帧边界；总线回读一致表示寄存器写入成功，不等同于画面已经稳定。

50Hz供电光源如果存在100Hz亮度起伏，可以把曝光约10ms（450行）作为对比点；不同LED/PWM频率需实际观察，不能保证都消除条纹。宽条纹、真实阴影边界以及大面积反射不能靠5×5高斯完整去除。

资料依据：本地`docs/resources/AR0135AT_RR_1.pdf`第12页曝光、第16页数字增益、第19页模拟增益、第21～22页AE与实际值回读。自动曝光所需嵌入数据/统计行保留原配置。

## 高斯本质及本轮改进

旧核为`[1,2,1]`的二维外积除16。其作用是局部低通：降低高频噪声，也会降低真实高频细节。简单提高所有权重而保持归一化不会增强降噪。

新选项串联第二级同核，内部等效一维`[1,4,6,4,1]`外积除256，中间有整数舍入，因此不宣称与一次5×5卷积逐位完全相等。单级一维方差0.5，两级合成方差1，平滑范围从3×3扩至5×5。第二级可独立旁路，增加的三拍对所有通路一致。

原“保边”是亮度范围门控：差值超过16的邻居被中心值替代，不是完整双边滤波；中心本身有脉冲噪声时可能保留噪声。本次保留它作可选对照，增强高斯第二级为普通平滑。并未把一个未经验证的复杂算法替换到良好的Sobel路径中。

合成均匀场叠加±8随机噪声、共同有效区域：原噪声平方误差108587，单级14950，双级8034，第二级比单级再降低约46.3%。这是合成数值结果，非摄像头实拍SNR，也不意味着所有物体纹理应被去除。

## Sobel与Scharr为什么相近

当前Sobel不是仅水平/垂直两个方向的教科书版本，而是已有八方向实现的四组正负方向响应取最大值，再以连续灰度强度显示。Scharr采用水平/垂直`3/10/3`梯度；二者都检测局部亮度变化，大轮廓相似是正常现象。

原Scharr采用`(|Gx|+|Gy|)/4`，同样长度的对角梯度在L1度量下会偏大。新增选项改用`(max(|Gx|,|Gy|)+3*min(|Gx|,|Gy|)/8)/4`近似L2。它降低角度带来的幅度差异，保留原L1作对比；不保证比当前八方向Sobel更好，也不自动补断边。Scharr仍输出连续强度，Canny则输出二值轮廓；显示风格差异本身就会让微小噪点显得更突出。

## Canny与连续性

链路仍为预平滑 → Scharr梯度 → 四方向NMS → 双阈值 → 连接。原固定低阈值为高阈值一半，只传播两轮；超过两跳的弱链会被丢弃。新低阈值比例25%～75%，并增加到可选六轮传播。候选值0/弱/强保留，只有相邻强边才可提升弱边；不会直接生成零梯度位置的边缘。孤立抑制在第一轮删除没有其他候选邻居的点，不会进行膨胀导致边线变粗。

渐变照明下的同一条合成弱轮廓，保持高低阈值不变，两轮保留23个像素，六轮保留31个像素。仍然不能保证连接任意长的弱边，真正低于低阈值或被NMS去掉的点也不能靠此恢复。本版**不是整帧递归Canny**；若需要完整滞后追踪，应另外设计整帧标签缓存和收敛传播/连通域遍历，不能把有限轮数称为全局算法。

通用窗口使用因果的前两行/列；每次中心运算使结果相对输入产生空间偏移，并扩大无效边界。本版六级连接始终占据固定流水，关闭增强只禁止后四级提升弱边，仍传递窗口中心标签。Canny有效区从至少左上22像素后开始（启用中值等上游有效掩码可能进一步扩大），显示坐标相对旧版Canny多出四行/列中心偏移；HDMI时序和1280×720总有效尺寸不变。原Sobel和原图的像素坐标保持原行为。

标准算法参考：[OpenCV Canny](https://docs.opencv.org/4.12.0/d7/de1/tutorial_js_canny.html)说明平滑、NMS、双阈值和强弱边连接；本工程有限邻域实现的限制如上。不要仅因算法名称更复杂就认为其在当前镜头/照度下必定优于Sobel。

### 串口新增命令

沿用13字节CRC8帧；一次一请求，不传图像。

- `14`：DATA0 flags，DATA1 low_percent，其余0；应答DATA为`status, flags, low_percent, 0,0,0,0,0`，帧边界应用后应答。
- `15`：全0查询，返回上述已应用设置。
- `40`：DATA0=0读/1写；DATA1～2寄存器LE16；DATA3～4值LE16，读时0；其余0。应答`status,valueLo,valueHi,0,0,0,0,0`。
- `40`错误：2非法参数，5未就绪/忙/超时，6I2C NACK重试失败。只允许代码白名单中的曝光/增益/AE寄存器，不能通过此命令改变复位、PLL或视频时序。I2C初始化和运行时共用同一主机。
- `12`：恢复原图、几何、调节项、摄像头设置，保留阈值与DDR已存帧；必须等待摄像头恢复序列结束才能回成功。部分失败会报告错误，不假称全部恢复。
