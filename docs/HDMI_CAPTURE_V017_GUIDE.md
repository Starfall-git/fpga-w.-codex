# V0.17 USB采集卡实时预览

连接方式：FPGA HDMI OUT → 采集卡 HDMI IN；采集卡 HDMI OUT → 显示器；采集卡 USB3.0 → 电脑。HDMI OUT直通与电脑预览独立。串口继续用于算法/阈值/DDR控制，不传图。

本版仅修改上位机和顶层版本注释，不修改RTL功能；继续使用V0.16比特流，无需重新综合下载。

## 操作

1. 启动 `python -m host.gui`（首次使用先 `python -m pip install -r host/requirements.txt`）。本机已在 `D:/python/python.exe` 中装好依赖。
2. 点击“HDMI预览”，选择 **Hagibis**。HD Webcam是另一台设备，不要误选。列表编号会随插拔变化，按名称选择。
3. 选择1280×720 / 60，点击“开始预览”。不需要连接串口也能预览；如需修改FPGA参数，再连接串口。
4. “保存当前帧到仓库”存入原本地帧仓库，可从主界面的本地图片仓库查看、编辑和多图对比。
5. “当前帧另存为…”可选择任意目录及PNG/JPEG文件名。保存的是点击时收到的完整分辨率帧，弹窗期间的后续帧不会替换它。此按钮保存静态图片，不是视频录像。
6. “停止”或关闭预览窗口释放采集卡；FPGA采集和HDMI直通显示不受上位机停止影响。

本地仓库默认在用户Pictures/VF-Ti60-FrozenFrames。另存为文件不自动登记到仓库，需要仓库编辑时使用“保存当前帧到仓库”。DDR冻结帧仍按编号管理；要保存其中某帧到电脑，先在DDR仓库回放到HDMI，等预览稳定后保存。此流程不会自动把USB收到的帧和某个DDR编号绑定。

## 实现及限制

`host/hdmi_source.py` 实现已有HDMIFrameSource边界，新增USBCaptureSource和预览控制；`host/gui.py`默认使用该适配器并保证只有一个预览窗口；依赖记录在`host/requirements.txt`；测试在`host/test_hdmi.py`。

OpenCV DirectShow负责采集，设备名称和索引由[cv2-enumerate-cameras](https://github.com/lukehugh/cv2_enumerate_cameras)提供。驱动打开、读帧和释放都在同一后台线程执行。采集只留最新帧，预览约30Hz刷新，显示保持比例。分辨率/帧率是请求值，设备可能协商成其他格式，状态栏报告实际尺寸和测得采集频率。2秒未更新不再把旧帧当作实时图像，也禁止保存；驱动异常后需停止再开始。若驱动阻塞，GUI不等待它，线程未退出前拒绝重复打开设备。

当前默认请求MJPEG，可用格式由采集卡决定。设备占用、Windows相机权限、HDMI未输入、USB线或端口带宽均可能影响采集。卡自身输出“无信号”图案仍是合法视频帧，软件不能仅凭收到帧判断HDMI场景有效。
