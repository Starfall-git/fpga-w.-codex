# V0.14 冻结帧仓库、编辑与多图对比

## 使用

1. 使用 `Ti60_AR0135.xml` 工程，下载 `outflow/Ti60_AR0135_v014_snapshot_gallery.bit`。
2. 安装 `python -m pip install -r host/requirements.txt`，运行 `python -m host.gui`，连接115200/8N1串口。
3. 先调整原图/Sobel/中值、阈值和几何设置，再点击 **冻结当前帧并入库**。HDMI画面冻结，GUI显示逐行下载进度。下载对象是当前处理后的1280×720 RGB888画面。
4. 下载成功后打开 **冻结帧合集**。**恢复实时**解除DDR帧锁定，之后可以继续冻结另一帧。也可以在冻结状态再次保存同一画面。
5. 点击仓库缩略图打开编辑。支持画笔及颜色/粗细、拖动框选裁剪、上下翻转、左右镜像、10%～500%图片尺寸缩放、查看缩放、撤销。**另存到仓库**创建新副本，原图不覆盖；**下载图片**导出PNG/JPEG。
6. 勾选两张或更多图片，点击 **对比所选**。布局按窗口和图片比例自动选择行列；每张图的 **打开/批注**按钮进入编辑器，另存后新图片出现在仓库，可再加入对比。

仓库默认路径：`~/Pictures/VF-Ti60-FrozenFrames`（本机通常为 `C:/Users/francis/Pictures/VF-Ti60-FrozenFrames`）。PNG和JSON元信息持久保存在电脑，关闭GUI和FPGA断电不影响已保存图片。编辑属于电脑端操作，不改变HDMI输出或DDR原始图像。对比视图展示选定版本，编辑后另存的新版本需重新勾选。

`python -m host.gui --demo` 可演示界面。模拟图片带 `SIMULATED FRAME - NOT CAMERA DATA` 标识及元信息，编辑副本继承模拟标志。

## DDR和传输边界

- DDR原有四帧缓冲继续工作。一次锁定一个显示帧，写入器跳过该帧，使用其他三个槽；解除冻结在读通道安全边界完成。
- **多帧历史在电脑仓库，不是在DDR中无限堆积**。必须完成下载，再恢复实时并冻结下一帧；不支持高速连续抓拍。FPGA复位会丢失尚未下载的冻结帧。
- UART115200下RGB888整帧2,764,800字节，纯数据理论约240秒；逐行等待下一帧及协议开销后通常约4～5分钟。冻结显示很快，但缩略图要在完整下载、校验和保存后才出现。
- 支持取消下载；当前行传输完成后响应取消，HDMI保持冻结，点击恢复实时可继续。不会发布半张图片。CRC失败、串口断开会报告错误，损坏图片不入库；流不完整时先断开重连。
- 冻结/下载时禁用阈值、模式和几何编辑，FPGA同时拒绝这些写命令，避免同一张图各行来自不同设置。物理阈值按键也被锁定。
- 重新连接会查询实际冻结状态；关闭GUI不自动释放冻结帧，重新连接后可恢复实时。旧bit不支持30命令时禁用冻结功能，既有控制及本地仓库仍可用。
- 捕获的是HDMI实际像素；若DDR读出欠载，显示中的黑行也会被记录。旧有错误标志为上电以来的粘滞状态，不能用历史错误拒绝所有后续截图。

## UART协议扩展

命令仍使用13字节帧 `A5 5A SEQ CMD DATA[8] CRC8`。命令号均为十六进制。CRC8多项式07，初值00，范围及既有协议相同。下列字节索引从0开始，多字节值小端。

| 命令 | 请求DATA | 应答DATA |
|---|---|---|
| 30 查询截图能力 | 全0 | 状态0、协议版本1、宽度LE16、高度LE16、格式3=RGB888、标志(bit0支持，bit1冻结) |
| 31 冻结/恢复 | byte0=1冻结或0恢复，其余0 | 既有标准状态包，冻结状态跨时钟确认后应答 |
| 32 读取行 | byte0..1=行号0～719，其余0 | 状态0、行号LE16、字节数LE16、格式3、0、0；之后紧接原始像素与CRC16 |

32成功应答之后发送 `RGB RGB ...` 共3840字节，再发送CRC16低字节、高字节。CRC16-CCITT多项式1021，初值FFFF，无反射、无最终异或，仅覆盖原始像素字节。上位机必须读完原始流再发下一命令，不得把像素字节当控制帧，也不得丢弃与应答同批到达的像素。

错误状态：2参数非法、3旧固件/功能未实现、4未冻结或冻结时配置被锁定、5视频/冻结等待超时。错误应答不跟随像素数据。READ_ROW等待下一次VS低电平后计数有效DE像素，只捕获请求行；支持停止后重新逐行下载。
